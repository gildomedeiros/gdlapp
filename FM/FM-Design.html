Surfer GPS patterns and pan response

Switch between these behaviours live in GP Simulator · Save or load a behaviour sequence

Same and opposite describe the paddle relative to the eventual ride. FM determines pan direction from changes in bearing as seen from the mount. Jitter means unwanted back-and-forth camera pan.

Pan can stop mid-ride when it catches up. FM sends pan Stop on the first encoder reading at or past the latest published target. If GP publishes a farther target in the same direction before pan reaches the current one, the same move continues. A restart requires pan to report stopped and a published target ahead in the commanded direction. If pan coasts past that target, FM waits for a farther one.

GP cache and LT handoff

  • At session start the published cache is null. LT displays Waiting for GP target, keeps checking the cache and skips tracking motor work until GP publishes coordinates with a direction. The operator’s Stop control remains available.
  • Use one snapshot containing latitude, longitude, source packet, position revision, position timestamp, freshness timestamp, state and clockwise or counterclockwise direction. Compute age from the freshness timestamp using the monotonic clock. Rule 0 can refresh freshness with the same coordinates, direction and revision. A state update alone also retains the revision.
  • Keep the latest raw receipt time separate from the published target’s age. Use the configured GPS age limit to determine whether a target can start a new move. Keep the last published direction during Stationary or a GPS gap. The active motor can finish toward its last target.
  • Compare bearings around the mount through north wrap. Use the first trusted fix as the initial comparison point for Rule 1. Compare each newer trusted bearing with its predecessor. A GPS gap clears pending votes before processing the next fix. A fix with unchanged bearing clears the streak. A bearing change in the already published direction clears a pending reversal. For a Stationary departure, use the saved stationary reference. A position publication resets the Rule 0 hold count.
  • Test input. For GP Simulator, feed the pad fixes directly into GP. In LoRa mode, the clockwise and counterclockwise test offsets can adjust receiver positions during Live Tracking. Keep the original GPS coordinates and mark the source. Rule 0 compares successive inputs before filtering.
  • Direction rule review. Rule 1 covers startup when there is no Stationary reference and reversal during movement. Rule 3 covers a departure from Stationary, including a departure before the first publication. Keep the one-fix departure and three-fix confirmation visible for review against the paddling-into-a-wave risk.

Live Tracking · Two reasons FM stops an active pan during normal tracking

  1. Pan reaches the latest published target. FM sends :K1 (request pan Stop) on the first valid encoder reading at or past that target. Pan can catch up between GPS publications, or GP can publish a closer target. In the manual test, GPS #2286 moved the target from 12 m to 10 m while the published direction stayed clockwise.
  2. GP publishes a reversal while pan is moving. FM requests Stop when the published direction is opposite the current slew. The raw reversal must pass GP’s direction rules. FM waits for pan to report stopped before starting in the new direction.

Live Tracking contract. LT gets all tracking targets and their direction from the GPS Data Producer (GP). Ask the user before changing Live Tracking or the GP-to-LT contract.

ON LIVE TRACKING PRESS
    Load fixed HS pan speed (default 800×) and calculate its step period once.
    Load fixed slow tilt speed (default 64×) and GP’s hold count X (default 4).
    Load GP’s stationary confirmation time (default 2,000 ms).
    Reset the GPS simulation offset and GP publication cache.
    Use one GTi worker and distinct recent UDP reply ports.
    Wait for each reply or timeout before sending the next command.

ON SIMULATION PRESS
    GP adds the selected signed 0.5 m or 2 m to the net offset for newly received fixes.

ON EACH RECEIVER PACKET
    GP records the raw fix from LoRa or the GP Simulator pad. Apply the test offset only to LoRa fixes.
    GP runs the GPS filter rules and updates its published snapshot when eligible.
    For Rule 2, start the confirmation clock at the first repeated coordinate.
    Enter Stationary after consecutive fixes stay within 1.5 m of that fixed position for the configured time.

TRACKING LOOP
    Read GP’s latest published coordinates, direction, revision, state and age.
    If the snapshot is null, show Waiting for GP target and return to the loop.
    If only age or state changed, keep the current target and direction.
    If the revision changed, calculate target counts from the published coordinates.
    Map GP’s clockwise or counterclockwise direction to the calibrated pan encoder sign.

    If GP publishes the opposite direction while pan is slewing:
        Send :K1 (request pan Stop) once and record the reversal.
        Mark pan as braking and continue on the next iteration.
        Require :f1 (read pan motor status) to report stopped before another pan Start.
        Use the latest GP publication for the next move.

    Before any new pan start, require a usable GP target and stopped pan status.
    Read :j1 (read pan encoder count) for the current pan count.
    If feedback fails during a slew, log the failure and keep the pan running.
    gap = (target count - current pan count) × GP direction sign
          using unwrapped counts

    IF gap > 0 AND pan is stopped:
        Send :G13<dir> (set HS pan mode and direction).
        Send :I1<period> (apply the fixed HS speed for this slew).
        After both setters acknowledge, send :J1 (start pan).

    ELSE IF gap <= 0 AND pan is slewing:
        Send :K1 (request pan Stop) once at the first valid reading at or past target.
        After that acknowledgment, dispatch tilt if needed and the GP target is usable.
        Send :f2 (read tilt motor status). Defer if tilt is moving.
        Send :j2 (read tilt encoder count). If tilt needs to move:
            Send :G22<dir> (set low-speed tilt GoTo mode and direction).
            Send :I2<period> (request the configured slow tilt speed).
            Send :S2<target24> (set absolute tilt target).
            Require successful setter replies, then send :J2 (start tilt).
            Record the Start reply. The GTi stops tilt at its target.

    OTHERWISE:
        Keep slewing toward the existing target if pan is running.
        If stopped, wait for the next GP position revision.

ON STOP LIVE TRACKING PRESS
    End the tracking loop and finish the outstanding exchange or let it time out.
    Send :K3 (request Stop for both motors) as the next command.
    Report its reply or timeout and save the matching KML and JSONL.
